## 当前阶段：M5 已完成，下一步 M6

已完成：

- Tauri 2 + React + TypeScript + Vite 初始化。
- Memento 应用标识、窗口标题和基础视觉壳。
- 左侧导航和主要功能入口占位。
- 产品、架构、开发和 ADR 文档系统。
- M0：产品场景细化（日记、未来信件、导出备份恢复）、SQLite 与编辑器选型 ADR、版本基线与验证命令。
- M1：Rust 数据目录初始化与 SQLite 迁移、五个日记命令、“今天”页真实创建与编辑、800 ms 自动保存与失败重试、切页与关闭前 flush、设置页显示数据位置。
- M2-01：正文换成 Tiptap，支持标题、引用、分隔线、链接、加粗、斜体和撤销重做；正文格式升到 version 2 并兼容旧正文。
- M2-02：图片导入与附件目录，正文只记附件 ID；自定义协议按 ID 读图，原文件移动或删除后仍可阅读；列表显示首图；迁移 v2 新增 `attachments` 表。
- M2-03：标签栏（规范化、去重、32 字符上限）、日记软删除、回收站页面与恢复；迁移 v3 新增 `tags`、`entry_tags` 表。
- M2-04：A02–A09 与 M1 用例在真实窗口回归，补上切页守卫——保存失败时切页会被拦下并提示，不再静默丢弃输入。
- M3-01：时间线按日期倒序分批加载（每批 40 篇）、月历按月显示有记录的日期与当天篇数、点任意日期进入当天日记并可补写；从时间线或月历进入时保留返回来源。
- M3-02：关键词、标签与日期范围的组合检索；结果按日期倒序分批加载、显示标题/摘要/首图并可进入对应日记；迁移 v4 新增 `search_text` 派生列并在升级时回填。
- M4-01：未来信箱的写信、锁定列表、到期阅读与独立回应；开启时刻按写信时区换算成 UTC 保存，状态在读取时按当前 UTC 推进，跨午夜、换时区与夏令时都不漂移；迁移 v5 新增 `letters` 表。
- M5-01：Markdown 导出。设置页选择目录后把全部未删除的日记写成「日期-标题.md」，图片复制到 images/ 并用相对路径引用；重名追加序号，目标不可写时报错。
- M5-02 至 M5-04：完整备份、预检与恢复。备份目录含 `VACUUM INTO` 快照、附件、缩略图与带 SHA-256 的 manifest；恢复前先预检并展示内容规模，再自动备份当前空间，最后在一条事务里换掉五张表；损坏、缺文件与版本过新的备份在恢复前被拒绝。

尚未完成：

- 前端测试、CI 和 Windows 安装发布验收（Rust 侧已有 `cargo test`）。

前端构建、Rust 检查与 13 个 Rust 测试通过；A01–A19 的桌面验收证据按阶段记录在 [development/iterations/](development/iterations/)（迭代 001 至 009），逐项状态见[验收清单](development/acceptance.md)。导航中未接入的入口、版本号和占位页面均不代表功能完成。

## P0：MVP 交付阶段

阶段按依赖推进，阶段编号在任务、验收和迭代记录中保持一致。

| 阶段 | 主要交付 | 完成门槛 | 状态 |
| --- | --- | --- | --- |
| M0 开发准备 | 细化产品场景、完成关键选型 ADR、建立验收数据与最小验证流程 | 能说明写入、保存成功和失败恢复的行为，M1 任务可执行 | 已完成 |
| M1 可靠保存 | SQLite 与迁移、最小日记创建/编辑、自动保存、重开 | 真实磁盘数据完整，失败与重试可验证 | 已完成 |
| M2 日记闭环 | 格式编辑、图片、标签、回收站与恢复 | 中文长文与多图可编辑、保存、删除和恢复 | 已完成 |
| M3 回看与检索 | 时间线、月历、日期详情、关键词/标签/日期筛选 | 多条路径均可找到同一批真实记录 | 已完成 |
| M4 未来信箱 | 写信、锁定、到期打开、回应 | 时区和边界正确，重开后原信与回应完整 | 已完成 |
| M5 导出与恢复 | Markdown 与图片、完整备份、校验与恢复 | 全新空间实际恢复后内容与关系完整，失败保留当前空间 | 已完成 |
| M6 Windows 发布 | 全链路回归、故障与性能检查、安装升级和发布说明 | 全部 P0 验收通过，无发布阻断缺陷 | 待开始 |

M1 到 M5 的阶段退出条件都已满足：“创建 → 自动保存 → 关闭重开 → 继续编辑 → 删除与恢复”的日记闭环、时间回看与组合检索、未来信箱的锁定与回应、Markdown 导出与完整备份恢复都已通过桌面验收。下一阶段是 M6：全链路回归、故障与性能检查、Windows 安装与保留数据升级。

容量假设为 1 名开发者、每周约 4 个有效开发日；含缓冲暂估约 11–16 周。尚未确定启动日期，M1 完成后重估，阶段通过验收后才更新状态。详细工作量和风险见开发计划。

## P1：MVP 稳定后评估

- 收藏卡片、主题收藏册和月份切片。
- 全局快速捕捉、最近阅读位置和草稿恢复细节。
- 应用锁和本地凭据保护；加密方案需要单独设计。

上述能力未开始实施；收藏册占位入口不构成提前交付。

## P2：暂不进入实施

- 自由画布、胶带和贴纸。
- 云同步、移动端和多人协作。
- AI 整理、摘要和年度回顾。
- 公开分享和社交功能。

进入 P1/P2 前重新确认产品范围、数据影响和需要的 ADR，不将这些能力插入当前 P0 关键链路。
