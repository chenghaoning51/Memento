# 功能：日记

- 状态：M0 细化完成；M1 实现最小闭环，M2 补齐富文本、图片与标签。
- 相关：[MVP 范围](mvp-scope.md)、[数据模型](../architecture/data-model.md)、[验收清单](../development/acceptance.md)。

## 目的

日记是 Memento 的基本单位：用户在某个本地日历日期上写下一段内容，关掉应用再打开，内容必须还在。

## 术语

- **日记（entry）**：一篇按日期归属的记录，有自己的稳定 ID。
- **保存**：把编辑器当前内容写入 SQLite 并确认写入成功。只有写入成功后，界面才能显示“已保存”。
- **草稿**：尚未保存成功的前端输入，只存在于内存中。

## 创建

1. 用户从“今天”页点击“写一篇”。
2. 应用立即创建一条日记并写入数据库：生成 UUID、记录 `entry_date`（本地日历日期）和 `created_at_utc`。
3. 创建成功后进入编辑状态；创建失败时停留在列表并显示错误，不进入编辑状态。

同一天可以有多篇日记，列表按 `created_at_utc` 升序显示。

标题和正文都为空时，列表显示“未命名的一页”。应用不会自动删除空日记——删除必须由用户主动发起，避免和回收站语义冲突。

## 编辑与自动保存

保存状态只有四个：

| 状态 | 含义 | 界面表现 |
| --- | --- | --- |
| `saved` | 磁盘内容与编辑器内容一致 | 显示“已保存”和最近保存时间 |
| `dirty` | 有未保存的修改 | 显示“未保存” |
| `saving` | 保存请求在途 | 显示“保存中” |
| `failed` | 最近一次保存失败 | 显示错误原因和“重试” |

规则：

- 用户输入后进入 `dirty`。
- 停止输入 800 毫秒后自动保存；连续输入期间最多每 5 秒强制保存一次，避免长时间不落盘。
- 保存成功进入 `saved`，同时更新 `updated_at_utc`。
- 保存失败进入 `failed`，保留当前输入，显示可理解的错误，用户可以重试。失败不得显示为已保存。
- 同一时刻只允许一个保存请求在途。在途期间的新输入进入排队，等当前请求结束后再保存最新内容；较早请求的结果不能覆盖较新的输入。
- 重试沿用同一条日记 ID，不新建记录。

## 切页与关闭

- 切页、切换日记、关闭窗口前先执行一次立即保存（flush）。
- flush 成功后才执行切换或关闭。
- flush 失败时取消切换或关闭，保留当前输入并显示错误；用户可以选择重试或继续编辑。
- 用户强制终止进程时，已经显示“已保存”的内容必须完整；未确认的内容不做任何承诺。

## 撤销与恢复

三种“恢复”是不同的事，不合并实现：

| 名称 | 含义 | 归属 |
| --- | --- | --- |
| 编辑撤销 | 撤销本次编辑中的输入 | 编辑器自身（M1 用文本框的系统撤销，M2 用编辑器撤销栈） |
| 保存失败恢复 | 保存失败后保留输入并重试 | 自动保存状态机 |
| 回收站恢复 | 把软删除的日记恢复为正常状态 | 回收站功能（M2） |

第一版不提供历史版本，也不把“撤销”当作跨会话的恢复手段。

## 回收站

- 删除是软删除：写入 `deleted_at_utc`，不物理删除行。
- 正常浏览、时间线和搜索都排除软删除的日记。
- 恢复即清空 `deleted_at_utc`，正文、附件和标签关系保持不变。
- 永久删除与自动清理的产品规则尚未确定，M1/M2 不实现；软删除不清附件。

## 日期与时区

- `entry_date` 是用户看到的本地日历日期，格式 `YYYY-MM-DD`，创建时由前端按系统时区确定，之后不随系统时区变化。
- `created_at_utc`、`updated_at_utc`、`deleted_at_utc` 保存 UTC 时间戳。
- 跨午夜继续编辑不改变 `entry_date`：归属看创建时的日期，不看最后一次修改时间。

## 边界

M1 不包含：富文本格式、图片、标签、回收站界面、历史版本、云同步。相关能力分别在 M2 及以后实现，未实现前不出现对应入口或占位按钮。
