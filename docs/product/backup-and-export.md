# 功能：导出、备份与恢复

- 状态：M0 确定范围与语义；M5-01 实现 Markdown 与图片导出，M5-02 至 M5-04 实现完整备份、预检与恢复。
- 相关：[MVP 范围](mvp-scope.md)、[数据模型](../architecture/data-model.md)、[验收清单](../development/acceptance.md)。

## 目的

用户可以把自己的内容带走，也可以在换机或重装后完整还原。

## 导出

- 范围：全部未删除的日记，按日期从早到晚。回收站里的日记不导出。勾选部分日记导出留到后续版本。
- 产物：Markdown 文件 + 图片文件，写入用户选择的目录。
- 文件名是「日期-标题」，标题为空时用摘要前 16 个字；Windows 不允许的字符换成空格，超过 60 字截断。
- 图片使用相对路径引用，导出后不依赖应用即可打开。
- 富文本降级规则：标题→`#`，引用→`>`，分隔线→`---`，链接→`[文本](url)`，图片→`![](相对路径)`。
- 目标目录存在同名文件时追加序号（「标题 (2).md」），不静默覆盖。
- 目标不可写时报错，不留下被当作成功的半成品。
- 导出成功后显示导出了几篇日记、几张图片和写到哪个目录；用户在系统对话框里取消时不提示错误。

## 备份

- 范围：完整空间——`memento.db` 的一致性快照、`attachments/`、`thumbnails/`、`manifest.json`。
- 备份产物是**一个目录**，名字形如 `memento-backup-20261018132500`，放在用户选的父目录下；同名时不会覆盖，因为名字带秒级时间戳。
- `manifest.json` 记录备份格式版本、应用版本、模式版本（`PRAGMA user_version`）、创建时间和文件清单，每个文件带字节数与 SHA-256。
- `manifest.json` 最后写：没有它的目录就是没写完的备份。
- 数据库快照用 `VACUUM INTO` 生成，不暂停写入；备份期间发生编辑或附件导入时，快照对应备份开始那一刻，之后的改动不会混进来。
- 只有校验通过、完整写完的备份才标记为有效；失败不产生“看起来成功”的备份。

## 恢复

- 按完整空间恢复设计，不做增量合并。
- 预检：manifest 是否存在、格式版本是否受支持、文件清单是否齐全、每个文件的 SHA-256 是否一致。预检通过后先展示这份备份有多少篇日记、多少封信、备份于何时，用户确认才继续。
- 恢复前自动把当前空间备份到数据目录的 `backups/`，保证可以回退；结果里给出这次自动备份的位置。
- 换行在一条数据库事务里完成：失败就回滚，当前空间一行都不变；附件与缩略图在事务成功后才替换。
- 预检失败或写入中断时，当前空间保持可打开，不留下半新半旧的数据。
- 恢复完成后重开应用核对正文、原图、标签、回收站、信件与回应。

## 不做什么

- 不做云端同步、选择性合并、加密备份；这些需要独立的安全与同步设计。
