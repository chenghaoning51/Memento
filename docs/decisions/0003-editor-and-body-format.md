# ADR-0003：M1 使用结构化纯文本正文，M2 再引入 Tiptap

- 状态：Accepted
- 日期：2026-10-17

## 背景

数据模型要求正文同时保存结构化 JSON 和纯文本副本，后者用于摘要和搜索。M1 的目标只是“创建 → 编辑 → 保存 → 重开继续编辑”，M2 才需要标题、引用、分隔线、链接、图片和标签。

候选编辑器：Tiptap（ProseMirror）、Lexical、Slate、原生 `textarea`。

## 决定

- M1 的正文使用纯文本 `textarea`，写入 `content_text`；`content_json` 保存一个最小文档结构 `{"type":"doc","content":[{"type":"paragraph","text":...}]}`，模式版本为 1。
- M2 引入 Tiptap 时读取并升级该结构；旧数据通过 `content_json` 的 `type` 字段识别，不依赖表结构变更。
- 正文格式的演进策略：`content_json` 顶层必须带 `"version"` 字段，读取时按版本决定解析方式，未知的高版本拒绝编辑而不是静默降级。

## 原因

- M1 的验收条目（A02–A05）只要求文本内容可靠保存，引入富文本编辑器会把 M1 变成编辑器和持久化同时验证，违反“一次只推进一条链路”的迭代规则。
- 原生 `textarea` 的中文输入法、粘贴和系统撤销行为由 WebView 提供，是中文长文风险最低的基线。
- 保留 `content_json` 字段并写入最小结构，可以让 M2 直接替换编辑器而不改数据库模式，避免 M2 一开始就做迁移。
- Tiptap 依赖体积和中文输入法行为尚未验证，按计划在 M2 前单独验证，不在 M0 就锁定。

## 备选方案

- M1 直接接入 Tiptap：编辑器和持久化两个风险叠加，出问题时无法区分是保存链路还是编辑器的问题，未采用。
- 只保存纯文本、M2 再做迁移：会导致 M2 必须迁移所有已有正文，且丢失结构来源，未采用。
- Lexical / Slate：生态和中文输入法验证成本高于 Tiptap，M2 验证后若 Tiptap 不达标再重新评估。

## 影响

- M1 不引入任何编辑器依赖，前端依赖保持不变。
- `content_json` 与 `content_text` 在 M1 同步写入；搜索与摘要统一读 `content_text`。
- M2 开始需要为正文格式新增 ADR 或修订本 ADR，并补充中文输入法与格式往返的验证证据。
