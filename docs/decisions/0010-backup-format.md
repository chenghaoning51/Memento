# ADR-0010：备份是一个目录，恢复在一条事务里换行

- 状态：Accepted
- 日期：2026-10-18

## 背景

M5-02 至 M5-04 要做完整空间备份与恢复。产品文档定了语义：备份覆盖 `memento.db`、`attachments/`、`thumbnails/` 与 `manifest.json`；manifest 记录应用版本、模式版本、文件清单与每个文件的 SHA-256；恢复前自动备份当前空间；预检失败或写入中断时当前空间必须保持可打开。

需要定的是容器形态与切换方式：备份打成单个压缩包还是目录；数据库快照怎么取才与附件一致；恢复时怎么换掉当前数据而不留下半新半旧的空间。

## 决定

- 备份是**一个目录**，不是压缩包：`memento.db`、`attachments/`、`thumbnails/`、`manifest.json`。目录名是 `memento-backup-<YYYYMMDDHHMMSS>`，放在用户选的父目录下。
- 数据库快照用 SQLite 的 `VACUUM INTO`：由 SQLite 自己写出一致快照，不需要暂停写入，也不需要自己搬 WAL。
- `manifest.json` 最后写，记录 `format`、`app_version`、`schema_version`、`created_at_utc` 与文件清单（相对路径、字节数、SHA-256）。没有 manifest 的目录就是没写完的备份。
- 恢复分三步：① 先 `inspect`（manifest 版本、清单齐全、逐个校验 SHA-256）；② 自动把当前空间备份到 `<root>/backups/`；③ 把备份内容复制到 `<root>/.restore/`，把里面的库升级到当前模式版本，然后在**一条事务**里删空并重新插入 `entries`、`attachments`、`tags`、`entry_tags`、`letters`，事务提交后再把 `attachments/` 与 `thumbnails/` 目录换成暂存的那一份。
- 换行时临时关闭 `foreign_keys`，事务结束再打开：批量删除与插入的顺序不可能同时满足所有外键。
- 恢复前如果备份来自更早的模式版本，先在暂存库里跑一次迁移（含 v4 的 `search_text` 回填），保证两边列数一致。

## 原因

- 用目录而不是压缩包：用户能直接看到备份里有什么、能单独取一张图；不需要引入压缩库；manifest 与文件在同一层，校验路径最简单。代价是文件多，但一次备份通常几十个文件。
- 用 `VACUUM INTO` 而不是复制 `memento.db`：WAL 模式下直接复制主库文件会丢掉还没 checkpoint 的事务，得到的是旧数据。`VACUUM INTO` 由 SQLite 读事务生成一致快照。
- manifest 最后写：备份目录的「完成」状态只需要看一个文件是否存在，不需要额外的锁文件或临时后缀。
- 恢复用「事务换行 + 目录替换」而不是「整库文件替换」：数据库文件被当前连接持有，Windows 上无法直接改名覆盖；用 `ATTACH` 把快照挂上来在事务里搬数据，失败就是回滚，当前空间一行都不变。附件目录是纯文件，用「先暂存、再删除旧目录、再改名」处理，失败时最多是附件目录缺失，不会污染数据库。
- 恢复前强制备份当前空间：这是产品承诺的「可回退」，也让「恢复错了」变成可以再恢复回来。

## 备选方案

- **打成一个 zip**：便于传输，但恢复时要先解压到临时目录，多一步磁盘开销；用户也不能直接翻看备份内容。
- **直接复制数据库文件**：会丢掉 WAL 里未 checkpoint 的数据，是真实的数据丢失风险。
- **关闭连接 → 换文件 → 重开**：能实现原子替换，但要求应用在这期间不响应任何请求；一旦换文件成功而附件目录失败，就变成半新半旧，正是产品文档禁止的状态。
- **只备份数据库，附件另行处理**：恢复后会出现引用缺失，违反「成功的备份内部不能出现引用缺失」。

## 影响

- 新增模块 `src-tauri/src/backup/mod.rs`；新增三个 Tauri 命令：`create_backup`、`inspect_backup`、`restore_backup`，命令总数变为二十八个。
- `AppError` 增加 `InvalidBackup(String)`，预检失败的信息直接给用户看（缺文件、校验不符、版本过新）。
- 设置页新增「备份与恢复」区块：备份到文件夹、从备份恢复；恢复前用系统对话框展示这份备份的篇数、信数与创建时间，确认后才执行。
- 备份目录里不写 `backups/`（不嵌套自己的历史备份），恢复前的自动备份写在当前空间的 `backups/` 下。
- 恢复不改变 `PRAGMA user_version`（两边已对齐到当前版本）；如果将来出现需要降级的备份，应当拒绝而不是猜测。
