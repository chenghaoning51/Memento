# Memento 文档系统

这里是 Memento 的单一文档入口。文档描述产品为什么存在、当前做什么、代码如何组织，以及重要决定为什么这样做。

## 文档分区

| 目录 | 用途 | 什么时候更新 |
| --- | --- | --- |
| `product/` | 愿景、用户体验和功能边界 | 用户流程或产品范围变化时 |
| `architecture/` | 模块边界、数据模型和基础设施 | 技术实现或数据契约变化时 |
| `development/` | 环境、命令、代码约定、开发计划与验收 | 开发流程、阶段安排或质量门槛变化时 |
| `decisions/` | 不容易逆转的技术和产品决策 | 选择方案或改变既有方案时 |
| `templates/` | 新文档和 ADR 的模板 | 文档流程需要扩展时 |

## 文档规则

- 文档描述当前真实状态；未实现的能力必须标记为“计划中”或“占位”。
- 每份文档只回答一个主要问题，跨主题内容通过链接连接。
- 重要决定写入 ADR，并记录背景、取舍和后续影响。
- 代码改动和文档改动放在同一个提交中，便于回看历史。
- 术语保持稳定：`日记` 是按日期组织的记录，`收藏` 是独立保存的片段，`未来信件` 是按日期开启的内容。

## 开发规划文档如何配合

- 路线图维护阶段状态和产品优先级。
- 开发计划描述当前实现、阶段依赖、任务编号、工作量假设和风险。
- 迭代流程定义开工条件、开发节奏、完成定义与缺陷处理。
- 验收清单提供可复现的场景和发布门槛；执行结果记录在实际迭代文档中。
