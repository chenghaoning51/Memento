```bash
pnpm build
```

## 验收环境与数据

至少使用一套 Windows 桌面环境，记录系统版本、CPU、内存、架构、WebView2、应用版本及提交号；无提交时记录工作区内容摘要。开发机验收和干净环境安装验收分别记录。业务验收断开网络，不依赖开发服务、远程图片、账号或云服务。

建立可重复生成或导入的合成数据，内容与文件不要使用真实私人记录：

| 数据集 | 内容 | 用途 |
| --- | --- | --- |
| F1 基本记录 | 空空间、同一天 3 篇日记、跨月/跨年记录、闰日；中文、英文、emoji 和中文标点 | 日期、排序、导航、创建与重开 |
| F2 编辑与图片 | 至少 20,000 个中文字符；引用、分隔线、链接；5 张本地图片，包含中文名、同名不同目录、空格路径 | 中文输入法、格式、正文与附件往返保存 |
| F3 检索 | 1,000 篇带已知关键词/标签/日期的日记；包含相似短语、不同标签交集和软删除项 | 关键词命中、组合条件、结果更新与初步性能 |
| F4 信件 | 开启时刻前/等于/后、跨午夜、重启后到期、原信与回应；至少一个存在夏令时变化的时区样例 | UTC、本地日期、锁定与回应 |
| F5 备份与故障 | 含上述业务关系、回收站和附件的完整空间；另备缺文件、改校验值、未知版本与不可写目录样例 | 备份、恢复、迁移和失败回退 |

图片支持格式与大小上限在 M2 产品细化时确定，正常样例在支持范围内；另准备超限或不支持的输入确认错误处理。大体积样例和生成物不直接作为仓库常规提交内容。

## 功能与可靠性验收矩阵

所有下列条目都是 MVP 发布所需标准。“阶段”表示首次必须通过的时点，后续涉及相关模块时需要回归。

| 编号 | 阶段 | 操作与输入 | 通过标准 |
| --- | --- | --- | --- |
| A01 | M1 | 空数据目录首次启动，再正常关闭并重开 | 数据库/目录初始化成功，迁移只执行一次；数据位置可查看；不会生成多个互相隔离的空间 |
| A02 | M1 | 新建中文日记，连续编辑，切页并关闭重开 | ID、本地所属日期、标题和正文一致；持久化成功后才显示已保存；重开可继续编辑 |
| A03 | M1 | 快速输入多次内容，制造前一保存请求较晚返回 | 最新确认保存的内容保留，较早结果不能覆盖新内容；保存提示与磁盘状态一致 |
| A04 | M1 | 用不可写路径或可控失败模拟保存错误，再恢复可写并重试 | 显示可理解的错误；不把失败标为已保存；当前输入仍在，重试后可重开核对 |
| A05 | M1 | 分别在未保存、保存中、已保存时切页或正常关闭；另在已保存后强制终止 | 正常切页/关闭满足 M0 确定的保存或保留/取消规则；失败可见；强制终止后已确认保存的数据完整；未确认数据不作虚假承诺 |
| A06 | M2 | F2 长文，中文输入法组合输入，粘贴、引用、分隔线、链接、撤销，保存并重开 | 文本、结构和顺序一致；撤销语义符合产品细化；搜索文本与正文同步 |

## 验证分层

只为能捕捉实际风险的行为建立测试：

| 层次 | 优先覆盖 | 接入时点 |
| --- | --- | --- |
| Rust 单元/集成 | 迁移、事务失败、附件引用、检索过滤、备份校验和恢复失败 | M1 开始，随能力补齐 |
| 前端业务/组件 | 自动保存乱序与失败、状态提示、日期转换、编辑器内容往返 | M1/M2 开始，先决定工具和依赖 |
| 桌面端到端与人工 | 中文输入法、窗口关闭重开、文件选择、离线读图、权限、安装升级 | 每阶段演示，M6 完整执行 |
| 文档与静态检查 | 构建、类型、链接、范围/实现状态一致 | 每个评审变更 |

选择工具后再增加测试脚本与 CI，并同步命令文档；当前不能直接假设存在 `pnpm test`。浏览器中的演示或模拟命令不能证明桌面持久化与文件行为正确。

## 验收记录与证据

每次执行在对应迭代记录中保存：

- 条目编号、执行人和时间、应用/工作区版本、系统与测试数据版本。
- 命令或操作步骤、预期结果、实际结果、通过/失败/阻塞及关联缺陷。
- 必要的截图、录屏、结构化数据摘要或文件校验值的位置；证据使用合成内容。
- 保存与恢复场景须在重开后核对，备份场景须实际恢复；只看到“成功”提示不构成证据。
- 自动化输出保存摘要和结果；复测说明原缺陷是否解决、已有核心流程是否回归。

大文件和运行产物保存在约定的外部证据位置，迭代记录提供可访问位置或摘要，不要求把私人数据和整份备份加入 Git。
