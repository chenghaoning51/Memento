A16 明细：

- 设置页点「导出为 Markdown」弹出系统目录选择框；选好目录后页面显示「已导出 7 篇日记、7 张图片到 …」。
- 导出目录里得到 7 个 `日期-标题.md` 与 `images/` 下 7 张 PNG；用 Pillow 读回，尺寸分别是 900×600、600×800、400×300 等，与原图一致，说明复制的是原图而不是缩略图。
- Markdown 降级逐项核对：`## M2 编辑器验收`（小标题 → `##`）、`> 写下来的东西，才真正属于自己。`（引用 → `>`）、`---`（分隔线）、`窗外的**梧桐叶**被打湿了。`（加粗 → `**`）、`这一段有*斜体*`、`[链接](https://example.com/x)`、`![a07-a.png](images/<附件ID>.png)`（图片 → 相对路径）。
- 用 Markdown 阅读器打开导出的文件，中文、标点与图片都能正常显示；图片路径相对于 md 文件，不依赖应用数据目录。
- 同一个目录再导出一次：文件名变成「… (2).md」，原有文件不被覆盖；图片已存在时不重复复制，第二次报告「0 张图片」。
- 目标不可写：把 `D:\Memento\README.md`（一个文件）当目录、以及不存在的 `Z:\nowhere` 分别调用导出，都返回可读错误（「文件操作失败：当文件已存在时，无法创建该文件。」「系统找不到指定的路径。」），没有留下半成品文件。
- 在系统对话框里点「取消」：页面不显示错误、按钮恢复可点，已有的导出结果行保持不变。

### 缺陷

| 级别 | 现象 | 处理 |
| --- | --- | --- |
| S3 | 导出文件名直接拼标题，Windows 不允许的字符（如 `\ / : * ?`）会让写盘失败 | 已处理：文件名过滤非法字符、折叠空白、去掉结尾的点并截到 60 字；标题为空时退回摘要前 16 字或「无题」 |

开发期另有一处环境问题：第一次用 `rfd` 直接在命令里弹窗，会和 WebView2 的 IPC 线程抢 COM；改为 `tauri-plugin-dialog` 后由插件的异步命令弹窗，问题消失（见 [ADR-0009](../decisions/0009-markdown-export.md)）。

### 风险与未完成项

- 导出范围是全部未删除的日记；勾选部分日记导出还没有界面，产品文档已注明留到后续版本。
- 标签、回收站与信件不进入 Markdown 导出；它们会在 M5-02 的完整备份里保留。
- 导出的图片名是附件 ID，对人不友好；正文里的引用是正确的，用户一般不需要看文件名。
- 导出是同步命令，日记很多时会占住 IPC 线程；当前规模（个位数到几百篇）下无感，M6 若出现卡顿再考虑改成后台任务并上报进度。
- 前端仍无测试与 CI；目录选择与取消路径靠桌面手工验证。
