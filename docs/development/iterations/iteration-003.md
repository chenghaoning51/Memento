A08 明细：

- 输入 `" 旅行   记录 "` 确认后，标签块显示 `旅行 记录`，首尾空白被去掉、内部连续空白折叠为一个空格。
- 再加 `Travel`，随后输入 `"  travel  "` 不新增标签块，大小写与空白差异被同一套规范化吃掉。
- 输入 33 个「一」被拒绝，标签栏显示「标签最多 32 个字符。」，输入框保留原文，未写入任何行；输入 32 个「二」被接受。
- 移除 `Travel` 后该日记剩 2 个标签，移除立即生效，不等正文自动保存。
- 连续切换 3 篇日记后，`.tag-bar` 与 `.editor-shell` 各只有 1 个，标签内容随日记切换正确刷新。
- 数据库核对：`tags` 4 行、`entry_tags` 3 行，与界面显示的标签一致；没有孤立关联。

A09 明细：

- 点日记页脚的「移到回收站」后，该日记从「今天」列表消失，列表从 4 条变 3 条，编辑区切到剩下最后一篇。
- 侧栏「回收站」页列出被删的「M2 编辑器验收」，文案为「2026年10月17日 删除于 18:50」，按删除时间从新到旧。
- 点「恢复」后回收站变空并显示「回收站是空的」；回「今天」页该日记回到列表（4 条）。
- 恢复后标签块仍是 `[旅行 记录, 二二…（32 个）, 工作]`，正文 4 张图的 `naturalWidth`/`naturalHeight` 为 600×800、900×600、600×800、800×500，与删除前一致。
- 数据库核对：`entries` 4 行的 `deleted_at_utc` 全为 NULL；`attachments` 5 行，磁盘上原图 5 个、缩略图 5 个；`entry_tags` 3 行、`tags` 4 行。删除与恢复都没有动附件文件和标签关系。

### 缺陷

| 级别 | 现象 | 处理 |
| --- | --- | --- |
| S2 | 每切换一次日记，正文上方多出一个空标签栏，切 3 篇就累积 3 个 | 已修复：标签栏与编辑器是同一 Fragment 的兄弟节点且都用了 `key={draft.id}`，React 报 duplicate key 并复用旧 DOM；改为 `tags-${id}` 与 `editor-${id}` 两个前缀不同的 key。复测连切 3 篇后各只剩 1 个，整页重载后控制台无报错 |
| S2 | 输入规范化后为空的标签（纯空白）会把标签栏清空 | 已修复：`add_entry_tag` 在规范化结果为空时改为返回该日记当前的标签列表，界面保持原样 |

### 风险与未完成项

- 标签立即写库、正文按 800 ms 自动保存，两者是独立事务；正文保存失败时已确认的标签不会回滚。产品上接受这一取舍，见 ADR-0006。
- 孤儿标签（不再被任何日记引用）不会被删除，等标签管理能力出现时再定规则。
- 永久删除与孤儿附件清理仍未实现，回收站里的日记和图片会一直留在磁盘上。
- 前端仍无测试与 CI，标签与回收站链路的保护来自 2 个新增 Rust 用例与桌面验收。
