A11 明细：

- 升级启动时 `user_version` 由 3 变为 4，旧数据按现有标题与正文回填 `search_text`，无需手工干预。
- 期望命中数由脚本按同一套折叠规则独立算出（均排除软删除）：下雨 330、散步 190、梧桐叶 141、雨天+散步 63、阅读 90、2026-09 区间 30、下雨+2026-09 10、下雨+阅读 30。
- 关键词「下雨」滚到底为 331 篇（330 篇合成加 1 篇 M2 留下的真实记录「今天下雨了。窗外的梧桐叶被打湿…」），331 条摘要无重复，首条 2026年10月17日、末条 2025年1月2日。
- 标签「阅读」= 90、「雨天」= 330、「雨天」+「散步」交集 = 63，与期望一致。
- 日期区间 2026-09-01 至 2026-09-30 = 30；区间再加「下雨」= 10。
- 点结果进入日记页：标题「2026年9月28日」、返回按钮「返回搜索」、侧栏高亮「搜索」，编辑器正文与列表摘要一致。
- 结果行显示日期、标题、创建时间与首图；没有标题的记录用摘要充当首行；空态在有条件时提示「换个词或去掉一些条件再试试。」，无条件时提示「还没有可以找回的记录。」。

A12 明细：

- 新建「鹈鹕测试：今天在河边看到一只鹈鹕。」→ 搜「鹈鹕」命中 1 篇。
- 把正文改成「改过的正文：河边只有白鹭。」并确认已保存 → 搜「鹈鹕」= 0（显示「没有找到」与「换个词或去掉一些条件再试试。」），搜「白鹭」= 1，说明 `search_text` 随保存更新，没有旧文本命中。
- 把该篇移到回收站 → 搜「白鹭」= 0，回收站里能看到该条并可恢复；恢复后搜「白鹭」= 1。
- 从搜索结果进入「第 654 篇」并移除「雨天」标签 → 再搜「雨天」= 329；把标签加回去 → 330，且结果里含「第 654 篇」。
- 分批加载与条件切换：滚到底 330 条后立刻点标签「雨天+散步」，结果为 63 条、右上角显示「找到 63 篇」，没有出现计数停在旧值或条数与计数不一致。

性能采样（debug 构建、1,006 篇）：关键词首屏 93–109 ms；关键词加日期区间 140 ms；滚动取完 990 条合计 5,375 ms；月历翻月 10 次样本 45–48 ms（p95 48 ms）；1,400 字正文输入到「已保存」864 ms。均低于 A21 的 1 s 首屏与 2 s 操作目标。

### 缺陷

| 级别 | 现象 | 处理 |
| --- | --- | --- |
| S2 | 正在追加批次时修改筛选条件，新条件的请求被在途批次吞掉：结果条数停在旧值，DOM 条数多于右上角计数 | 已修复：`runSearch` 的「追加批次且正在加载」提前返回只对追加生效，条件变化一律从 offset 0 重查；并加请求序号，晚回来的旧请求不覆盖新结果 |
| S2 | 右上角计数写死「找到 N 篇」，分批加载时少报 | 已修复：按状态显示「已读 N 篇」/「找到 N 篇」/「全部记录」/「没有找到」 |

### 风险与未完成项

- 检索是全表 `LIKE` 扫描，成本随篇数线性增长；1,006 篇下无感，M6 若出现可感知延迟再评估 FTS5 或 n-gram 索引（见 [ADR-0007](../decisions/0007-search-strategy.md)）。
- `search_text` 是派生列，若将来直接拷贝数据库文件恢复，需要重跑一次回填。
- 不做相关度排序、高亮与分词；标签筛选是交集，不提供并集或排除条件。
- 前端仍无测试与 CI；搜索页的空态、错态靠桌面手工验证。
